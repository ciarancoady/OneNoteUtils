# Development roadmap

## Current status

The original C# rewrite roadmap is complete. The following follow-up work identified
during the August 2026 repository review is also complete:

- Detect pages moved between sections or section groups during incremental sync.
- Preserve manifest entries and exported files outside an active section or page filter.
- Add repeatable `--page` / `-p` filtering by exact page title or OneNote page ID.
- Extract CLI operations into a testable application service.
- Add integration coverage for incremental sync cleanup, full export manifests, and
  push create/update behavior.
- Add Push Plan preflight, explicit Page targeting, safe batch validation, and rollback.

## Next work

### Slice 0: Runtime-state hygiene

- Stop tracking `.onenote-sync.json`; it contains machine-specific absolute paths and
  OneNote Page IDs.
- Ignore `.onenote-sync.json` wherever it may be created in the repository.
- Keep Sync Manifests in user-selected output directories as runtime state, not source.
- Ignore known local scratch directories only when they are generated by this project.
- Confirm a fresh clone starts without a manifest and creates one on first Sync or Push.

### Slice 1: Page timestamps

- Add optional creation time to the Page model; retain the existing last-modified time.
- Parse OneNote's `dateTime` and `lastModifiedTime` hierarchy attributes.
- Emit `created_at` and `modified_at` as ISO-8601 UTC YAML only when values exist.
- Treat both fields as read-only export metadata; Push must not overwrite OneNote's
  system timestamps.
- Cover parsing, conditional frontmatter, timestamp formatting, and incremental-sync
  compatibility.

### Slice 2: Image presentation

- Add an optional Image Presentation value object containing alt text, display width,
  and display height.
- Parse OneNote image alt text and `<one:Size>` dimensions independently from binary
  pixel dimensions.
- Parse Obsidian embeds with `|WIDTH` and `|WIDTHxHEIGHT`; infer height from the
  intrinsic aspect ratio when only width is supplied.
- Use explicit presentation dimensions when writing OneNote XML, falling back to
  intrinsic dimensions.
- Keep Obsidian image embeds as the default export format and serialize dimensions.
  Alt text remains available to standard-Markdown paths but may be lost in the default
  Obsidian embed.
- Cover pull, Push, missing metadata, width-only scaling, and round-trip behavior.

### Slice 3: Rich table-cell round trips

- Treat table cells as recursive Content Element containers in both Markdown parsing and
  Obsidian writing.
- Preserve paragraphs, formatted Runs, images, bullet and numbered lists, and nested
  tables in document order.
- Use a real HTML parser for HTML required inside Markdown table cells; do not parse
  nested HTML with regular expressions.
- Reuse the normal image resolver and Push Plan validation for images inside table cells.
- Render nested OneNote tables and lists without introducing the synthetic code-block
  table structure known to crash OneNote.
- Preserve rich cell content on OneNote → Markdown → OneNote round trips.
- Cover mixed content, nested structures, image failures, escaping, and deeply nested
  validation.

### Slice 4: Structured target diagnostics

- Replace nullable Section lookup results with a structured resolution result.
- Distinguish a Notebook that is not open in the OneNote desktop client from a missing
  Section inside an open Notebook.
- Exclude recycle-bin Notebooks and Sections from target resolution.
- Return bounded, actionable candidate names, prioritizing close Section matches.
- Use one resolver consistently in Push Plan construction and future hierarchy commands.
- Cover case-insensitive matches, Section Groups, closed Notebooks, missing Sections,
  recycle-bin entries, and candidate formatting.

### Slice 5: Safe Page hierarchy targeting

- Add an optional parent Page target to Push so a newly created Page can become a
  subpage.
- Support a separate operation for moving an existing Page under another Page without
  rewriting either Page's content.
- Prefer exact parent Page ID targeting; permit title targeting only when it resolves to
  exactly one Page in the target Section.
- Reject missing or duplicate parents, self-parenting, moves beneath descendants, and
  targets outside the selected Section.
- Compute Page Level from the resolved parent and place the moved Page after the
  parent's existing descendant subtree, preserving sibling order.
- Include hierarchy mutations in dry-run output and capture enough hierarchy state to
  restore the original position and Page Level if mutation fails.
- A Push requesting a parent must fail and clean up a newly created Page if nesting
  cannot be completed; it must never silently leave the Page at the Section root.
- Cover root and nested parents, existing descendants, duplicate titles, cycles,
  rollback, cleanup, and COM hierarchy XML generation.

### Slice 6: Append Push

- Add **Append Push** as an explicit single-file operation that adds Content Elements to
  an existing Page without replacing its current content.
- Require an exact target Page ID and verify that it belongs to the selected Notebook
  and Section.
- Allow an optional anchor that must resolve to exactly one insertion point; a missing or
  ambiguous anchor fails instead of falling back silently.
- Define insertion relative to the matched Content Element, with end-of-Page append as
  an explicit mode rather than an error fallback.
- Run normal Markdown parsing, image resolution, hyperlink checks, and complete
  preflight before mutation.
- Preserve existing OneNote object IDs and binary content while inserting new elements.
- Capture original Page XML and restore it if the update fails.
- Include the target, anchor, insertion mode, and element count in dry-run output.
- Cover image/object-ID preservation, multiple outlines, exact anchor matching,
  missing/duplicate anchors, empty fragments, validation failures, and rollback.

### Slice 7: Portable formatting fidelity

- Add Markdown highlight combinations that map cleanly to the existing Run model.
- Preserve explicit, source-derived font and sizing metadata only where the domain model
  supports it; do not hard-code team-, notebook-, or template-specific styles.
- Keep code blocks as safe shaded monospace paragraphs and avoid restoring synthetic
  table rendering.
- Derive table widths from portable content or presentation metadata, not recognized
  column names; leave widths unlocked unless OneNote requires locking for fidelity.
- Add representative round-trip fixtures rather than examples tied to a specific team
  template.

### Deferred

- HTML capture and sanitization: defer until a user-facing web or local-HTML clipping
  workflow is required.
- Attachment size summaries: defer until Markdown Attachment Push is designed.
- Public Page deletion: internal deletion remains available for failed-Push cleanup, but
  no user-facing delete command is planned.

## Delivery order

1. Runtime-state hygiene.
2. Page timestamps and Image Presentation as independent formatting slices.
3. Rich table-cell round trips.
4. Structured target diagnostics.
5. Safe Page hierarchy targeting.
6. Append Push.
7. Portable formatting fidelity.

Structured target diagnostics must land before Page hierarchy targeting. Rich table-cell
support should land before Append Push so appended fragments use the same recursive
content and validation behavior as replacement Push.
